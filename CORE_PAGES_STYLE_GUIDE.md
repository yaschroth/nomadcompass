# Core Pages Style & SEO Guide — The Nomad HQ

Source of truth for the **homepage, hub pages, tool pages, the author page, and utility/auth
pages** — every page type that is not a blog post, city page, or accommodation listing. Those
have their own guides ([`BLOG_STYLE_GUIDE.md`](BLOG_STYLE_GUIDE.md),
[`CITY_PAGE_STYLE_GUIDE.md`](CITY_PAGE_STYLE_GUIDE.md),
[`ACCOMMODATION_PAGE_STYLE_GUIDE.md`](ACCOMMODATION_PAGE_STYLE_GUIDE.md)).

Shared rules (clean self-canonical URLs, em-dash ban, one `<h1>`, mobile parity) are the same as
the blog; see [`BLOG_STYLE_GUIDE.md`](BLOG_STYLE_GUIDE.md).

## 1. Sitewide entities — declare ONCE, on the homepage

The homepage [`index.html`](index.html) is the only place that declares the site-level identity.
Add two JSON-LD blocks to its static `<head>` (currently it has none):

```json
{ "@context":"https://schema.org","@type":"Organization",
  "name":"The Nomad HQ","url":"https://thenomadhq.com/",
  "logo":"https://thenomadhq.com/assets/logo-256.svg",
  "sameAs":["https://www.linkedin.com/in/yannick-schroth/","https://www.instagram.com/ynncks/"] }
```
```json
{ "@context":"https://schema.org","@type":"WebSite",
  "name":"The Nomad HQ","url":"https://thenomadhq.com/" }
```

**Declare `Organization` and `WebSite` exactly once, here.** Never add a second `Organization`
entity on another page — Google dedups competing organisation entities unpredictably and it
dilutes the publisher signal. (The `publisher` Organization *inside* a blog post's `BlogPosting`
is a property of that article and is fine; it is not a second standalone entity.) Reuse the same
`sameAs` set as the author/blog so identity stays consistent ([author.cjs](scripts/lib/author.cjs)
holds the canonical social URLs).

If/when on-site search exists, add a `potentialAction` `SearchAction` to the `WebSite` block.

## 2. Homepage (`index.html`)

- **`<title>`** ≤ 60, no em-dash. Current title `The Nomad HQ — Find Your Next City` uses an
  em-dash; change to `The Nomad HQ: Find Your Next City`.
- **`robots: max-image-preview:large`** (missing) + keep the existing OG/Twitter (already good:
  7 OG + 4 Twitter tags, branded `og-image.png`).
- Self-canonical `https://thenomadhq.com/` (present).
- **JSON-LD:** `Organization` + `WebSite` (section 1), plus optionally a `WebPage`.
- **Crawlable city grid (known gap).** The homepage city grid is JS-rendered, so the raw HTML has
  ~1 city link. Discovery of the 410 city pages must not depend on JS. This is already mitigated
  by the static [`/cities`](/cities) hub linked from the nav/footer; keep that link present, and
  ideally render a static set of city links into the page too. Never let the only path to city
  pages be runtime JS. See [`CITY_PAGE_STYLE_GUIDE.md`](CITY_PAGE_STYLE_GUIDE.md) §6.

## 3. Hub / collection pages (`blog.html` → `/blog`, `cities.html` → `/cities`)

These are list/index pages whose SEO job is to **funnel crawl + equity to the items they list**.

- **JSON-LD:** `CollectionPage` + `BreadcrumbList` (Home → Blog / Home → Cities):
  ```json
  { "@context":"https://schema.org","@type":"CollectionPage",
    "name":"Digital Nomad City Guides","url":"https://thenomadhq.com/cities",
    "isPartOf":{"@type":"WebSite","url":"https://thenomadhq.com/"} }
  ```
- **`robots: max-image-preview:large`** (add to `blog.html`; `cities.html` already has it — the
  [generator](scripts/generate_cities_hub.cjs) emits it).
- **Real `<a href>` links to every item** in the static HTML (no JS-only infinite scroll / "load
  more"). `cities.html` already lists all 410 cities; `blog.html` must list every article card
  with a real link (it does). If the list grows long, paginate with real `<a href="/blog/page/2">`
  links, not a JS button.
- One `<h1>` describing the collection; keyword-bearing. Unique title + meta description.
- The cities hub is generated by [`scripts/generate_cities_hub.cjs`](scripts/generate_cities_hub.cjs)
  — change the template there, not the output file, and re-run.

## 4. Tool pages (`wheel.html` → `/wheel`, `rentals.html` → `/rentals`)

> **Rentals is hidden for now** (`noindex`, off the nav and sitemap — see `TODO.md`). The guidance
> below applies to it only when it is brought back; until then it needs nothing. `/wheel` is live.

Interactive/app-like pages. They are indexable and in the sitemap, so they still need the basics:

- Complete the **`<head>`**: `robots: max-image-preview:large`, full Open Graph (wheel/rentals
  currently have only 3–4 OG tags and no Twitter card — complete them), self-canonical (present).
- **JSON-LD:** `WebApplication` (for the wheel decision tool) or `WebPage`; `CollectionPage` for
  rentals if it lists properties. Add a `BreadcrumbList` (Home → Wheel / Home → Rentals).
- Give each a **real, crawlable text description** of what the tool does and an `<h1>` — an
  app-only page with no indexable text ranks for nothing. Make sure the core value (and links to
  city/blog content) exists in the static HTML, not only after JS runs.
- House style applies: no em-dashes in any visible copy.

## 6. Utility / auth pages (`login.html`, `signup.html`, `profile.html`)

These have **no search value** and should be kept out of the index:

```html
<meta name="robots" content="noindex, follow">
```

- Add `noindex, follow` to `login`, `signup`, and `profile` (currently they are indexable by
  default — they're not in the sitemap, but Google can still find and index them via links).
- They do **not** need a self-canonical pointing elsewhere; `noindex` is the correct signal.
- `follow` keeps their nav/footer links live so equity still flows to real content.
- Keep them functional and fast; they are not SEO surfaces.

---

## 7. Stale / shell files (`index-shell.html`)

[`index-shell.html`](index-shell.html) is a near-duplicate of the homepage (same title, same
shell) and is served at `/index-shell`. A duplicate of the homepage is a duplicate-content and
crawl-waste risk. Do one of:

- **Delete it** if it is an unused leftover (preferred), or
- Add `<meta name="robots" content="noindex">` and make sure nothing links to it.

Audit periodically for other orphaned `.html` files at the repo root that ship to production but
aren't linked or intended to rank, and `noindex`/remove them.

## 8. Per-page checklist

**Indexable core pages (home, hubs, tools):**
- [ ] Clean URL 200; self-canonical = `og:url`; no em-dash in `<title>` (≤ 60).
- [ ] `robots: max-image-preview:large`; full OG + Twitter card.
- [ ] JSON-LD present and valid: homepage = `Organization` + `WebSite` (declared once site-wide);
      hubs = `CollectionPage` + `BreadcrumbList`; tools = `WebApplication`/`WebPage` + `BreadcrumbList`.
- [ ] Exactly one `<h1>`; real indexable text (not a JS-only shell).
- [ ] Lists items via real static `<a href>` links (no JS-only discovery).
- [ ] In `sitemap.xml`.

**Utility/auth/shell pages:**
- [ ] `robots: noindex, follow` (or `noindex` for the shell); not in `sitemap.xml`.
- [ ] `index-shell.html` deleted or noindexed; no other orphan root `.html` indexable.

**Everywhere:** no em-dashes; exactly one `Organization` entity site-wide; mobile parity.
